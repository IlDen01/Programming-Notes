# Sparse Table (разреженная таблица)

## Теория

Структура для ответа на запросы **идемпотентной** функции (min, max, gcd, and, or...) на отрезке массива за `O(1)`, без возможности изменения элементов.

Нужно уметь:

* отвечать на запрос `min`/`max`/... на отрезке `[l, r]` за `O(1)`
* строить структуру один раз за `O(n log n)`

Не поддерживает изменение элементов после построения.

---

## Идея

Для каждой позиции `i` заранее считаем ответы на отрезках длины `2^k`, начинающихся в `i`.

Ключевой момент — идемпотентность операции (например `min(x, x) = x`): благодаря этому можно покрыть отрезок `[l, r]` двумя, возможно **пересекающимися**, блоками степени двойки, и это не испортит ответ.

Хранится:

* `st[k][i]` — ответ на отрезке `[i, i + 2^k - 1]`
* `log[i]` — предпосчитанный `⌊log2(i)⌋`, чтобы не считать логарифм на каждый запрос

---

## Предпосчёт логарифмов

Чтобы быстро находить `⌊log2(len)⌋` для длины отрезка запроса.

```c++
std::vector log(n + 1, -1);
for (int i = 1; i < n + 1; i++) {
    log[i] = log[i / 2] + 1;
}
```

### Объяснение

* `log[1] = log[0] + 1 = 0` — отрезок длины 1 покрывается блоком `2^0`
* каждое следующее значение — это `log[i / 2] + 1`, то есть на сколько раз можно поделить `i` на 2
* по сути инкрементальный пересчёт целочисленного логарифма без `std::log`

---

## Построение таблицы

Базовый случай — отрезки длины `1`, дальше каждый следующий уровень собирается из двух предыдущих.

```c++
std::vector st(log[n] + 1, std::vector(n, INT_MAX));
for (int i = 0; i < n; i++) {
    st[0][i] = a[i];
}
for (int k = 1; k <= log[n]; k++) {
    for (int i = 0; i + (1 << k) <= n; i++) {
        st[k][i] = std::min(st[k - 1][i], st[k - 1][i + (1 << (k - 1))]);
    }
}
```

### Объяснение

* `st[0][i]` — отрезок длины `2^0 = 1`, это просто сам элемент `a[i]`
* `st[k][i]` собирается из двух блоков длины `2^(k-1)`:
    * левый блок: `[i, i + 2^(k-1) - 1]` → `st[k - 1][i]`
    * правый блок: `[i + 2^(k-1), i + 2^k - 1]` → `st[k - 1][i + 2^(k - 1)]`
* условие `i + (1 << k) <= n` — блок не должен выходить за границы массива
* сложность построения — `O(n log n)`, так как для каждого `k` проходим почти весь массив

---

## Ответ на запрос

Отрезок `[l, r]` покрывается двумя блоками длины `2^k`, где `k = ⌊log2(r - l + 1)⌋`: один начинается в `l`, другой заканчивается в `r`. Они могут пересекаться — это не проблема благодаря идемпотентности `min`.

```c++
int k = log[r - l + 1];
int ans = std::min(st[k][l], st[k][r - (1 << k) + 1]);
```

### Объяснение

* `k` — максимальная степень двойки, укладывающаяся в длину отрезка
* `st[k][l]` — блок от `l` длиной `2^k`
* `st[k][r - (1 << k) + 1]` — блок, заканчивающийся в `r`, той же длины
* вместе они покрывают весь `[l, r]`, возможно с перекрытием в середине
* для операций без идемпотентности (например суммы) так делать нельзя — пришлось бы дробить отрезок на непересекающиеся блоки, и запрос был бы `O(log n)`

---

## Асимптотика

* построение: `O(n log n)`
* запрос: `O(1)` — для идемпотентных операций (min, max, gcd, and, or)
* память: `O(n log n)`
* изменение элемента: не поддерживается (нужно перестраивать таблицу)

---

## Применения

* статические запросы minimum/maximum на отрезке (RMQ)
* LCA через сведение к RMQ по обходу Эйлера
* запросы gcd/and/or на отрезке без изменений
* как быстрая альтернатива дереву отрезков, когда обновлений нет

---

## Готовая реализация

```c++
int n, m; // количество элементов и количество запросов соответственно
std::cin >> n >> m;
std::vector<int> a(n); // массив чисел

std::vector log(n + 1, -1);
for (int i = 1; i < n + 1; i++) {
    log[i] = log[i / 2] + 1;
}

std::vector st(log[n] + 1, std::vector(n, INT_MAX));
for (int i = 0; i < n; i++) {
    st[0][i] = a[i];
}
for (int k = 1; k <= log[n]; k++) {
    for (int i = 0; i + (1 << k) <= n; i++) {
        st[k][i] = std::min(st[k - 1][i], st[k - 1][i + (1 << (k - 1))]);
    }
}

int l, r;
int k = log[r - l + 1];
int ans = std::min(st[k][l], st[k][r - (1 << k) + 1]);
```
