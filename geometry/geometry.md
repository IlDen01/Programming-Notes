# Геометрия

## Теория

Базовый набор примитивов и операций для вычислительной геометрии на плоскости:

* задание точки и прямой
* проверка принадлежности точки прямой / лучу / отрезку / углу
* вычисление расстояний
* пересечение отрезков и прямых
* сдвиг, ориентированное расстояние, симметрия относительно прямой

---

## База

### Скалярное произведение векторов

$\vec{a} \cdot \vec{b} = |\vec{a}| \cdot |\vec{b}| \cdot \cos \alpha = a.x \cdot b.x + a.y \cdot b.y$

В коде обозначается `*`.

### Векторное (псевдоскалярное) произведение векторов

$\vec{a} \times \vec{b} = |\vec{a}| \cdot |\vec{b}| \cdot \sin \alpha = a.x \cdot b.y - a.y \cdot b.x$

В коде обозначается `^`.

## Принадлежность точки промежутку

### Принадлежность точки прямой

Точка $P$ принадлежит прямой $AB$, если $\vec{AB}$ коллинеарен $\vec{AP}$.

```c++
if (sign(AB ^ AP) == 0) {
    return true;
} else {
    return false;
}
```

### Принадлежность точки лучу

Точка $P$ принадлежит лучу $AB$, если принадлежит прямой $AB$ и $\vec{AB}$ со-направлен с $\vec{AP}$.

```c++
if (sign(AB ^ AP) == 0 && sign(AP * AB) >= 0) {
    return true;
} else {
    return false;
}
```

### Принадлежность точки отрезку

Точка $P$ принадлежит отрезку $AB$, если она принадлежит лучу $AB$ и $\vec{BA}$ со-направлен с $\vec{BP}$.

```c++
if (sign(AB ^ AP) == 0 && sign(AP * AB) >= 0 && sign(BA * BP) >= 0) {
    return true;
} else {
    return false;
}
```

Если точка уже гарантированно лежит на прямой, вместо второй и третьей проверки можно ограничиться bounding box'ом отрезка.

### Принадлежность точки углу

Угол $AOB$, точка $P$.

```c++
if (sign(OA ^ OP) * sign(OA ^ OB) >= 0 && sign(OB ^ OP) * sign(OB ^ OA) >= 0) {
    return true;
} else {
    return false;
}
```

## Расстояния

### Расстояние от точки до прямой

Вычисляется из площади треугольника, образованного точками $A$ и $B$, задающими прямую, и точкой $P$.

$S_{\triangle ABP} = \frac{1}{2} |AB| \cdot |PH| = \frac{1}{2} |\vec{AB} \times \vec{AP}|$

Отсюда $|PH| = \dfrac{|\vec{AB} \times \vec{AP}|}{|AB|}$.

```c++
long double dist = abs(AB ^ AP) / AB.len();
```

### Расстояние от точки до луча (отрезка)

Нужно проверить, что высота из $P$ на прямую $AB$ падает также и на сам луч (отрезок).

Проверка (НУО начало луча/отрезка в точке $A$):

```c++
if (AB * AP < 0) {
    dist = AP.len();
} else {
    dist = PH.len();
}
```

Для отрезка аналогично нужно проверить второй конец ($BA * BP$) и взять минимум из полученных расстояний.

### Ориентированное (знаковое) расстояние

Обычное расстояние от точки до прямой не учитывает, по какую сторону прямой лежит точка. Знаковый вариант:

$$d = \frac{ax+by+c}{\sqrt{a^2+b^2}}$$

```c++
long double d = (a * P.x + b * P.y + c) / sqrtl(a * a + b * b);
```

#### Идея

* числитель $ax+by+c$ — это (с точностью до нормировки) проекция точки на нормаль $\vec n=(a,b)$
* модуль $d$ — обычное евклидово расстояние до прямой
* знак $d$ показывает сторону: совпадает с направлением, куда "смотрит" нормаль $(a,b)$ — там $d>0$, с противоположной стороны $d<0$
* удобно, когда нужно одним вычислением получить и расстояние, и полуплоскость

## Пересечение отрезков

Отрезки $AB$ и $CD$ пересекаются, если:

$$sign(\vec{AB} \times \vec{AD}) \cdot sign(\vec{AB} \times \vec{AC}) \leqslant 0$$
$$sign(\vec{CD} \times \vec{CA}) \cdot sign(\vec{CD} \times \vec{CB}) \leqslant 0$$
$$\max(L_x) \leqslant \min(R_x), \quad \max(L_y) \leqslant \min(R_y)$$

```c++
if (sign(AB ^ AD) * sign(AB ^ AC) <= 0 && sign(CD ^ CA) * sign(CD ^ CB) <= 0 &&
    max(L_x) <= min(R_x) && max(L_y) <= min(R_y)) {
    return true;
} else {
    return false;
}
```

## Уравнение прямой

### Каноническая форма (через угловой коэффициент)

```c++
long double k_AB = (B.y - A.y) / (B.x - A.x);
long double b_AB = A.y - k_AB * A.x;
```

Не работает для вертикальных прямых ($x = const$) — угловой коэффициент там не определён.

### Общий вид (через нормаль)

Прямая в общем виде: $ax+by+c=0$, тройка $(a,b,c)$ задаёт прямую, причём $a^2+b^2>0$ (иначе это не прямая).

Вектор $\vec n=(a,b)$ перпендикулярен прямой — это **вектор нормали**.

Пусть прямая проходит через точки $P_1(x_1,y_1)$ и $P_2(x_2,y_2)$:

$$\begin{cases} ax_1+by_1+c=0 \\ ax_2+by_2+c=0\end{cases}$$

Вычитаем одно уравнение из другого:

$$a(x_2-x_1)+b(y_2-y_1)=0$$

Это в точности скалярное произведение $(\vec{P_1P_2},\ \vec n)=0$.

```c++
a = P1.y - P2.y;
b = P2.x - P1.x;
c = -a * P1.x - b * P1.y;
```

#### Идея

* нормаль $\vec n=(a,b)$ перпендикулярна прямой, значит перпендикулярна и любому вектору вдоль неё, в частности $\vec{P_1P_2}=(x_2-x_1,\ y_2-y_1)$
* коэффициенты $a,b$ берутся прямо из координат $\vec{P_1P_2}$, повёрнутых на $90°$
* $c$ подбирается так, чтобы уравнение обнулялось в точке $P_1$

### Направляющий вектор прямой

Поворот вектора на $90°$: $(x,y)\perp(-y,x)$.

Значит вектор, перпендикулярный нормали $\vec n=(a,b)$ (то есть лежащий вдоль самой прямой), — это $(-b,a)$.

```c++
Point dir = {-n.b, n.a};
```

### Ближайшая к началу координат точка прямой

Точка прямой $ax+by+c=0$, ближайшая к $(0,0)$, а через параметр $k$ — любая точка прямой:

$$\left(\frac{-ca}{a^2+b^2} - bk,\ \ \frac{-cb}{a^2+b^2} + ak\right)$$

```c++
Point p0 = {-c * a / (a * a + b * b), -c * b / (a * a + b * b)};
Point onLine = p0 + Point{-b, a} * k;
```

#### Идея

* при $k=0$ получается именно проекция начала координат на прямую
* слагаемое с $k$ сдвигает точку вдоль направляющего вектора $(-b,a)$, то есть вдоль самой прямой

### Перенос прямой вдоль нормали

Прямая $ax+by+c=0$ с нормалью $\vec n=(a,b)$. Если сдвинуть каждую её точку на расстояние $d$ вдоль единичной нормали:

$$x \to x' = x + \frac{ad}{\sqrt{a^2+b^2}}, \qquad y \to y' = y + \frac{bd}{\sqrt{a^2+b^2}}$$

то, подставив $x,y$ через $x',y'$ в исходное уравнение, получаем уравнение сдвинутой прямой:

$$a\left(x'-\frac{ad}{\sqrt{a^2+b^2}}\right)+b\left(y'-\frac{bd}{\sqrt{a^2+b^2}}\right)+c=0$$

$$ax'+by'+c-d\cdot\frac{a^2+b^2}{\sqrt{a^2+b^2}}=0 \implies ax'+by'+\left(c-d\sqrt{a^2+b^2}\right)=0$$

```c++
long double norm = sqrtl(a * a + b * b);
long double c_shifted = c - d * norm;
```

#### Идея

* нормаль $(a,b)$ задаёт направление, перпендикулярное прямой
* сдвигаем прямую целиком как множество точек на $d$ вдоль этого направления (делим на длину нормали, так как $(a,b)$ не обязательно единичный)
* коэффициенты $a,b$ у результата те же (прямая осталась параллельна исходной), меняется только свободный член $c$

## Пересечение прямых

### Через угловой коэффициент

```c++
const long double x = (b_CD - b_AB) / (k_AB - k_CD);
const long double y = k_AB * x + b_AB;
```

Не работает, если хотя бы одна из прямых вертикальна.

### Через общий вид (метод Крамера)

Пусть прямые заданы в общем виде:

$$\begin{cases} a_1x+b_1y+c_1=0 \\ a_2x+b_2y+c_2=0\end{cases}$$

Домножаем первое уравнение на $b_2$, второе на $b_1$ и вычитаем:

$$(a_1b_2-a_2b_1)\cdot x + c_1b_2-c_2b_1=0 \implies x = \frac{c_2b_1-c_1b_2}{a_1b_2-a_2b_1}$$

Аналогично, домножая на $a_2$ и $a_1$:

$$(b_1a_2-b_2a_1)\cdot y + c_1a_2-c_2a_1=0 \implies y = \frac{c_1a_2-c_2a_1}{a_1b_2-a_2b_1}$$

```c++
long double D = a1 * b2 - a2 * b1;
long double x = (c2 * b1 - c1 * b2) / D;
long double y = (c1 * a2 - c2 * a1) / D;
```

#### Идея

* знаменатель $D=a_1b_2-a_2b_1$ — это векторное произведение нормалей $\vec n_1 \times \vec n_2$
* способ работает всегда, в отличие от формы с угловым коэффициентом, которая не определена для вертикальных прямых

#### Разбор случаев по $D$

* $D\neq 0$ — прямые пересекаются в единственной точке
* $D=0$ — нормали коллинеарны, прямые параллельны:
    * если точка одной прямой лежит на другой — прямые совпадают
    * иначе — не пересекаются вовсе

## Симметричная точка относительно прямой

Дана точка $C$ и прямая $ax+by+c=0$ с нормалью $\vec n=(a,b)$. Нужно найти точку $C'$, симметричную $C$ относительно прямой.

Считаем ориентированное расстояние от $C$ до прямой:

$$d = \frac{aC_x+bC_y+c}{\sqrt{a^2+b^2}}$$

Тогда основание перпендикуляра и симметричная точка:

$$H = C - d\cdot\frac{\vec n}{|\vec n|}, \qquad C' = C - 2d\cdot\frac{\vec n}{|\vec n|}$$

```c++
Point reflect(const Point& C, long double a, long double b, long double c) {
    long double len = sqrtl(a * a + b * b);
    long double d = (a * C.x + b * C.y + c) / len;
    Point n_unit = {a / len, b / len};
    return {C.x - 2 * d * n_unit.x, C.y - 2 * d * n_unit.y};
}
```

#### Идея

* ориентированное расстояние $d$ сразу даёт и величину, и направление сдвига (знак учитывает сторону прямой)
* $H$ получается смещением $C$ на $-d$ вдоль единичной нормали — это одно "плечо" перпендикуляра
* $C'$ лежит по другую сторону прямой на таком же расстоянии, поэтому смещение вдвое больше: $-2d$ вдоль единичной нормали
* весь путь от $C$ до $C'$ считается за одно вычисление, без явного нахождения $H$

## Пересечение окружности и прямой

### Теория

Окружность с центром $O$ и радиусом $r$, прямая $ax+by+c=0$. Нужно определить:

* пересекаются ли окружность и прямая
* если да — найти точки пересечения (одну при касании, две при пересечении)

### Идея

Всё сводится к расстоянию от центра $O$ до прямой.

Пусть $d$ — расстояние от $O$ до прямой, $H$ — основание перпендикуляра (проекция $O$ на прямую).

* $d > r$ — прямая не пересекает окружность
* $d = r$ — прямая касается окружности, единственная точка пересечения — $H$
* $d < r$ — прямая пересекает окружность в двух точках, симметричных относительно $H$

Если пересечение есть, точки пересечения лежат на прямой на расстоянии $\sqrt{r^2-d^2}$ по обе стороны от $H$ (половина хорды — катет прямоугольного треугольника с гипотенузой $r$ и катетом $d$).

---

### Нахождение точек пересечения

```c++
std::vector<Point> intersect(long double a, long double b, long double c, const Point& O, long double r) {
    long double len2 = a * a + b * b;
    long double len = sqrtl(len2);

    long double d = (a * O.x + b * O.y + c) / len;

    if (sign(fabsl(d) - r) > 0) {
        return {};
    }

    Point H = {O.x - a * d / len, O.y - b * d / len};

    if (sign(fabsl(d) - r) == 0) {
        return {H};
    }

    long double half = sqrtl(r * r - d * d);
    Point dir = {-b / len, a / len};

    return {
        {H.x + dir.x * half, H.y + dir.y * half},
        {H.x - dir.x * half, H.y - dir.y * half}
    };
}
```

#### Объяснение

* $d$ — ориентированное расстояние от $O$ до прямой, знак не важен, поэтому сразу берём `fabsl`
* $H$ — проекция $O$ на прямую: сдвигаем $O$ на $-d$ вдоль единичной нормали $\left(\frac{a}{|\vec n|}, \frac{b}{|\vec n|}\right)$
* `dir` — единичный направляющий вектор прямой (нормаль, повёрнутая на $90°$)
* от $H$ откладываем `half` в обе стороны вдоль `dir`, получая две точки пересечения
* сравнение $d$ и $r$ через `sign` и вычитание, а не через `<`/`>`, чтобы аккуратно обработать касание при погрешностях вычислений с плавающей точкой

---

### Асимптотика

Все вычисления — константное число арифметических операций и одно извлечение корня.

```c++
O(1)
```

## Пересечение двух окружностей

### Теория

Даны две окружности: $(O_1, r_1)$ и $(O_2, r_2)$. Нужно определить взаимное расположение окружностей и, если они пересекаются, найти точки пересечения (одну при касании, две при пересечении).

---

### Идея

Всё определяется расстоянием $d=|O_1O_2|$ между центрами в сравнении с $r_1$ и $r_2$.

Два способа решения:

* **перебор случаев** — классифицировать расположение по $d$, $r_1$, $r_2$ и явно посчитать точки пересечения через геометрию треугольника
* **радикальная ось** — свести задачу к уже решённой задаче "прямая и окружность"

---

## Способ 1: перебор случаев

### Классификация по расстоянию между центрами

* $d > r_1+r_2$ — окружности не пересекаются, одна снаружи другой
* $d = r_1+r_2$ — внешнее касание, одна точка
* $|r_1-r_2| < d < r_1+r_2$ — две точки пересечения
* $d = |r_1-r_2|$ (и $d\neq0$) — внутреннее касание, одна точка
* $d < |r_1-r_2|$ — одна окружность строго внутри другой, пересечений нет
* $d = 0$ и $r_1=r_2$ — окружности совпадают, пересечение — вся окружность

### Нахождение точек пересечения

```c++
std::vector<Point> intersectCircles(const Point& O1, long double r1,
                                     const Point& O2, long double r2) {
    long double d = (O2 - O1).len();

    if (sign(d) == 0 && sign(r1 - r2) == 0) {
        return {};
    }
    if (sign(d - (r1 + r2)) > 0 || sign(d - fabsl(r1 - r2)) < 0) {
        return {};
    }

    long double a = (d * d + r1 * r1 - r2 * r2) / (2 * d);
    long double h2 = r1 * r1 - a * a;

    Point dir = (O2 - O1) * (1 / d);
    Point P = O1 + dir * a;

    if (sign(h2) == 0) {
        return {P};
    }

    long double h = sqrtl(h2);
    Point perp = {-dir.y * h, dir.x * h};

    return {P + perp, P - perp};
}
```

### Объяснение

* центры и точки пересечения образуют равнобедренную конфигурацию: точка пересечения $X$ удовлетворяет $|O_1X|=r_1$, $|O_2X|=r_2$
* `a` — расстояние от $O_1$ до основания перпендикуляра $P$, опущенного из точек пересечения на прямую $O_1O_2$ (получается из теоремы Пифагора для обоих треугольников $O_1PX$ и $O_2PX$)
* `h` — высота от $P$ до точек пересечения, то есть половина хорды
* `dir` — единичный вектор вдоль $O_1O_2$, `perp` — он же, повёрнутый на $90°$ и домноженный на `h`
* точки пересечения — это $P$, сдвинутая на `perp` в обе стороны
* случай совпадения окружностей ($d=0$, $r_1=r_2$) вырожденный — точек пересечения бесконечно много, возвращаем пустоту как признак особого случая (обрабатывается отдельно на вызывающей стороне)

## Способ 2: через радикальную ось

### Идея

**Радикальная ось** двух окружностей — множество точек, имеющих одинаковую степень относительно обеих окружностей. Если окружности пересекаются, обе точки пересечения лежат на радикальной оси — значит, достаточно построить эту прямую и пересечь её с одной из окружностей (уже решённая задача "прямая и окружность").

Радикальная ось всегда перпендикулярна линии центров $O_1O_2$.

### Вывод уравнения

Окружности в развёрнутом виде:

$$x^2+y^2-2x_1x-2y_1y+(x_1^2+y_1^2-r_1^2)=0$$
$$x^2+y^2-2x_2x-2y_2y+(x_2^2+y_2^2-r_2^2)=0$$

Вычитаем второе уравнение из первого — квадратичные члены $x^2+y^2$ сокращаются, остаётся линейное уравнение:

$$2(x_2-x_1)x+2(y_2-y_1)y+\left[(x_1^2+y_1^2-r_1^2)-(x_2^2+y_2^2-r_2^2)\right]=0$$

Это прямая $ax+by+c=0$ с:

```c++
a = 2 * (O2.x - O1.x);
b = 2 * (O2.y - O1.y);
c = (O1.x * O1.x + O1.y * O1.y - r1 * r1) - (O2.x * O2.x + O2.y * O2.y - r2 * r2);
```

### Нахождение точек пересечения

```c++
std::vector<Point> intersectCirclesRadical(const Point& O1, long double r1,
                                            const Point& O2, long double r2) {
    long double a = 2 * (O2.x - O1.x);
    long double b = 2 * (O2.y - O1.y);
    long double c = (O1.x * O1.x + O1.y * O1.y - r1 * r1)
                   - (O2.x * O2.x + O2.y * O2.y - r2 * r2);

    return intersect(a, b, c, O1, r1);
}
```

Используется функция `intersect` из раздела "Пересечение окружности и прямой" — радикальная ось пересекается с любой из двух окружностей, результат один и тот же.

### Объяснение

* вычитание уравнений убивает квадратичные члены — остаётся прямая, это и есть суть метода
* нормаль радикальной оси $(a,b)=2(O_2-O_1)$ — она пропорциональна вектору $O_1O_2$, отсюда перпендикулярность линии центров
* дальше задача сводится к уже готовому коду пересечения прямой с окружностью, повторно решать геометрию треугольника не нужно
* все случаи расположения (нет пересечения / касание / две точки) автоматически обрабатываются внутри `intersect` через сравнение расстояния от центра до прямой с радиусом

---

## Асимптотика

Оба способа выполняют константное число арифметических операций и один-два `sqrt`.

```c++
O(1)
```

---

## Применения

* поиск точек пересечения окружностей в геометрических задачах
* построение диаграммы пересечений/касаний набора окружностей
* вычисление площади объединения/пересечения кругов через границы дуг
* радикальная ось также используется отдельно — например, для нахождения радикального центра трёх окружностей (пересечение трёх радикальных осей)

## Поворот вектора на угол

### Теория

Дан вектор $\vec v=(x,y)$, нужно получить вектор, повёрнутый на угол $\alpha$ (против часовой стрелки, если $\alpha>0$).

---

### Идея

Поворот — линейное преобразование, задаётся матрицей поворота:

$$\begin{pmatrix}x'\\y'\end{pmatrix}=\begin{pmatrix}\cos\alpha & -\sin\alpha\\ \sin\alpha & \cos\alpha\end{pmatrix}\begin{pmatrix}x\\y\end{pmatrix}$$

Отсюда:

$$x'=x\cos\alpha-y\sin\alpha,\qquad y'=x\sin\alpha+y\cos\alpha$$

Длина вектора при повороте не меняется, меняется только направление.

```c++
Point rotate(const Point& v, long double alpha) {
    long double c = cosl(alpha);
    long double s = sinl(alpha);
    return {v.x * c - v.y * s, v.x * s + v.y * c};
}
```

#### Объяснение

* каждая координата нового вектора — это проекция старого вектора на повёрнутые оси
* знак минус у $\sin\alpha$ в формуле для $x'$ и плюс в формуле для $y'$ — это то, что задаёт направление поворота против часовой стрелки при положительном $\alpha$
* если нужен поворот по часовой стрелке — просто передать $-\alpha$ (или поменять знаки у $\sin$)

---

### Частные случаи (без тригонометрии)

Для угла $90°$ синус и косинус константны ($\cos 90°=0$, $\sin 90°=1$), поэтому поворот на $90°$ можно и нужно писать без вызова `sin`/`cos` — быстрее и без погрешностей плавающей точки.

**Поворот на $90°$ против часовой стрелки:**

$$(x,y) \to (-y,x)$$

```c++
Point rotate90(const Point& v) {
    return {-v.y, v.x};
}
```

**Поворот на $90°$ по часовой стрелке:**

$$(x,y) \to (y,-x)$$

```c++
Point rotateMinus90(const Point& v) {
    return {v.y, -v.x};
}
```

Именно поворотом на $90°$ получается направляющий вектор прямой из нормали ($(-b,a)$ из вектора $(a,b)$) и наоборот — нормаль из направляющего вектора.

---

### Поворот вокруг произвольной точки

Чтобы повернуть точку $P$ вокруг центра $C$ на угол $\alpha$: переносим в начало координат, поворачиваем, переносим обратно.

```c++
Point rotateAround(const Point& P, const Point& C, long double alpha) {
    Point shifted = {P.x - C.x, P.y - C.y};
    Point rotated = rotate(shifted, alpha);
    return {rotated.x + C.x, rotated.y + C.y};
}
```

#### Объяснение

* поворот вокруг произвольного центра не является линейным преобразованием (линейные преобразования всегда фиксируют начало координат) — поэтому его нельзя выразить одной матрицей без сдвига
* трюк: сдвигаем систему координат так, чтобы центр поворота совпал с $(0,0)$, поворачиваем в этой системе (уже линейно), сдвигаем обратно

---

### Асимптотика

Поворот на произвольный угол — одно вычисление $\sin$/$\cos$ и несколько арифметических операций:

```c++
O(1)
```

Поворот на $90°$ — константное число арифметических операций без тригонометрии:

```c++
O(1)
```

---

### Применения

* построение перпендикуляров и направляющих векторов прямой
* повороты фигур в задачах на геометрию
* задачи на вращающиеся конфигурации (например, вращающийся калипер)
* приведение вектора к каноническому направлению при сортировке по полярному углу

## Касательная из точки к окружности

### Теория

Дана окружность $(O,r)$ и точка $P$ снаружи окружности. Нужно найти точки касания $T_1, T_2$ — точки на окружности, в которых касательные, проведённые из $P$, касаются окружности.

Из точки вне окружности всегда можно провести ровно **две** касательные, симметричные относительно прямой $OP$.

---

### Идея

Ключевой факт: в точке касания радиус $OT$ перпендикулярен касательной $PT$. Значит треугольник $OTP$ — прямоугольный, с прямым углом при вершине $T$.

* гипотенуза — $|OP|=d$
* один катет — $|OT|=r$
* значит угол $\angle TOP$ фиксирован: $\cos(\angle TOP)=\dfrac{r}{d}$

То есть точки касания — это точки на окружности, отклонённые от направления на $P$ на угол $\pm\arccos(r/d)$.

Отдельно нужно учесть три случая расположения $P$ относительно окружности:

* $d>r$ — точка снаружи, есть две касательные
* $d=r$ — точка на окружности, касательная одна, и точка касания — сама точка $P$
* $d<r$ — точка внутри, касательных нет

---

### Нахождение точек касания

```c++
std::vector<Point> tangentPoints(const Point& O, long double r, const Point& P) {
    Point OP = P - O;
    long double d = OP.len();

    if (sign(d - r) < 0) {
        return {};
    }
    if (sign(d - r) == 0) {
        return {P};
    }

    long double angle = acosl(r / d);
    Point dir = {OP.x / d, OP.y / d};

    Point t1 = O + rotate(dir, angle) * r;
    Point t2 = O + rotate(dir, -angle) * r;

    return {t1, t2};
}
```

#### Объяснение

* `dir` — единичный вектор от центра $O$ в направлении $P$
* `angle` — угол между $OP$ и радиусом до точки касания, из прямоугольного треугольника $OTP$
* поворачиваем `dir` на $\pm\text{angle}$ и откладываем от центра длину $r$ — получаем сами точки касания $T_1,T_2$ на окружности
* случай $d=r$ вырожденный: точка касания совпадает с $P$, касательная в этой точке перпендикулярна $OP$

---

### Применения

* построение общих касательных двух окружностей
* задачи на видимость / обход препятствий-окружностей кратчайшим путём
* triangulation и построение выпуклой оболочки с дугами
* задачи на минимальный охватывающий путь вокруг круглых объектов

## Касательные к двум окружностям

### Теория

Даны две окружности $(O_1,r_1)$ и $(O_2,r_2)$. Общие касательные бывают двух типов:

* **внешние** — обе окружности лежат по одну сторону от касательной (2 штуки)
* **внутренние** — окружности лежат по разные стороны от касательной, то есть касательная проходит "между" окружностями (2 штуки)

Итого до 4 общих касательных, в зависимости от взаимного расположения окружностей.

Далее считаем $r_1\geqslant r_2$ (если нет — просто меняем окружности местами).

---

## Идея

Обе задачи сводятся к уже решённой задаче: **касательная из точки к окружности**.

Хитрость в том, чтобы за счёт изменения радиуса одной из окружностей "стянуть" вторую окружность в точку — тогда общая касательная двух окружностей превращается в касательную из точки к одной окружности, а после — восстанавливается параллельным переносом.

* для **внешних** касательных радиус большей окружности уменьшают на $r_2$ — тогда обе исходные касательные становятся касательными из $O_2$ к окружности $(O_1,\,r_1-r_2)$
* для **внутренних** касательных радиус большей окружности увеличивают на $r_2$ — тогда исходные касательные становятся касательными из $O_2$ к окружности $(O_1,\,r_1+r_2)$

В обоих случаях направление $\vec n$ от $O_1$ до точки касания на вспомогательной окружности задаёт направление сдвига для восстановления реальных точек касания на обеих исходных окружностях.

---

## Внешние касательные

### Построение

1. Строим вспомогательную окружность $(O_1,\,r_1-r_2)$
2. Находим точки касания $T_1,T_2$ из $O_2$ к этой окружности (см. раздел про касательную из точки к окружности)
3. Направление $\vec n=\dfrac{T-O_1}{r_1-r_2}$ — единичная нормаль касательной линии
4. Реальные точки касания получаются сдвигом центров вдоль $\vec n$: на окружности 1 на $r_1$, на окружности 2 на $r_2$

```c++
std::vector<std::pair<Point, Point>> externalTangents(const Point& O1, long double r1,
                                                        const Point& O2, long double r2) {
    long double auxR = r1 - r2;
    std::vector<Point> Ts = tangentPoints(O1, auxR, O2);

    std::vector<std::pair<Point, Point>> result;
    for (const Point& T : Ts) {
        Point n = (T - O1) * (1 / auxR);
        Point P1 = O1 + n * r1;
        Point P2 = O2 + n * r2;
        result.push_back({P1, P2});
    }
    return result;
}
```

### Объяснение

* уменьшая радиус большей окружности на $r_2$, "сжимаем" зазор между окружностями до нуля — теперь можно применить готовую формулу касательной из точки
* $T$ на вспомогательной окружности — это точка, откуда касательная параллельна искомой; направление $\vec n=(T-O_1)/\text{auxR}$ и есть та самая нормаль, вдоль которой обе исходные окружности "выступают" в сторону касательной
* сдвигая $O_1$ на $r_1\cdot\vec n$ и $O_2$ на $r_2\cdot\vec n$ (в одну и ту же сторону), получаем пару точек касания на одной прямой — обе окружности остаются по одну сторону от неё, что и характеризует внешнюю касательную
* особый случай $r_1=r_2$: вспомогательная окружность вырождается в точку $O_1$, тогда $\vec n$ надо брать перпендикулярно $O_1O_2$ (обе внешние касательные параллельны линии центров)

---

## Внутренние касательные

### Построение

1. Строим вспомогательную окружность $(O_1,\,r_1+r_2)$
2. Находим точки касания $T_1,T_2$ из $O_2$ к этой окружности
3. Направление $\vec n=\dfrac{T-O_1}{r_1+r_2}$
4. Точка касания на окружности 1: сдвиг $O_1$ на $r_1\cdot\vec n$ (в ту же сторону, что и $T$). Точка касания на окружности 2: сдвиг $O_2$ на $-r_2\cdot\vec n$ (в противоположную сторону — окружности лежат по разные стороны от касательной)

```c++
std::vector<std::pair<Point, Point>> internalTangents(const Point& O1, long double r1,
                                                        const Point& O2, long double r2) {
    long double auxR = r1 + r2;
    std::vector<Point> Ts = tangentPoints(O1, auxR, O2);

    std::vector<std::pair<Point, Point>> result;
    for (const Point& T : Ts) {
        Point n = (T - O1) * (1 / auxR);
        Point P1 = O1 + n * r1;
        Point P2 = O2 - n * r2;
        result.push_back({P1, P2});
    }
    return result;
}
```

### Объяснение

* увеличивая радиус большей окружности на $r_2$, "раздуваем" её так, чтобы касание из $O_2$ учитывало зазор, который в реальности займёт вторая окружность, лежащая по другую сторону линии
* знак минус при сдвиге $O_2$ (в отличие от внешних касательных, где знак был плюс) — ключевое отличие: он и обеспечивает то, что окружности оказываются по разные стороны от касательной
* внутренние касательные существуют, только если окружности не пересекаются и не лежат одна в другой, то есть $d=|O_1O_2| > r_1+r_2$ — это условие уже проверяется внутри `tangentPoints` (если $d\leqslant r_1+r_2$, `tangentPoints` вернёт пустой список или одну точку касания)

---

## Все 4 касательные

```c++
std::vector<std::pair<Point, Point>> allTangents(Point O1, long double r1,
                                                   Point O2, long double r2) {
    if (r1 < r2) {
        std::swap(O1, O2);
        std::swap(r1, r2);
    }

    auto result = externalTangents(O1, r1, O2, r2);
    auto internal = internalTangents(O1, r1, O2, r2);
    result.insert(result.end(), internal.begin(), internal.end());
    return result;
}
```

#### Разбор случаев по расстоянию $d=|O_1O_2|$

* $d > r_1+r_2$ — окружности не пересекаются, все 4 касательные существуют
* $d = r_1+r_2$ — внешнее касание, внутренние касательные вырождаются в одну (общую) в точке касания
* $|r_1-r_2| < d < r_1+r_2$ — окружности пересекаются, внутренних касательных нет, только 2 внешние
* $d = |r_1-r_2|$ — внутреннее касание, внешние касательные вырождаются в одну
* $d < |r_1-r_2|$ — одна окружность строго внутри другой, касательных нет вовсе

---

## Асимптотика

```c++
O(1)
```

Оба построения — константное число арифметических операций и один `acos`/`sqrt` внутри `tangentPoints`.

* построение ремня/троса, натянутого между двумя шкивами (внешние касательные)
* построение восьмёрки/перекрещенного ремня (внутренние касательные)
* задачи на кратчайший путь вокруг круглых препятствий
* нахождение минимального выпуклого контура, огибающего набор окружностей

## Площадь многоугольника

### Теория

Дан многоугольник, заданный последовательностью вершин $P_1,P_2,\dots,P_n$ (по часовой стрелке или против — неважно, для не самопересекающегося многоугольника). Нужно посчитать его площадь.

* многоугольник не обязательно выпуклый
* обход вершин против часовой стрелки даёт положительную площадь, по часовой — отрицательную (это удобно использовать как признак ориентации)

---

## Идея

Оба способа — метод трапеций и триангуляция из начала координат — на самом деле один и тот же приём с разной геометрической интерпретацией, дающий одну и ту же формулу — **формулу площади Гаусса** (shoelace formula):

$$S = \frac{1}{2}\left|\sum_{i=1}^{n}(x_i y_{i+1} - x_{i+1} y_i)\right|$$

где индексы берутся по модулю $n$ (после последней вершины снова идёт первая).

---

## Способ 1: метод трапеций

### Идея

Для каждого ребра $P_iP_{i+1}$ рассматриваем трапецию, образованную этим ребром и его проекциями на ось $Ox$ (по сути — прямоугольную трапецию с основаниями $y_i$ и $y_{i+1}$ и высотой $x_{i+1}-x_i$).

Площадь такой трапеции со знаком:

$$S_i = \frac{(y_i+y_{i+1})}{2}\cdot(x_{i+1}-x_i)$$

Знак зависит от направления обхода ребра относительно оси $Ox$: если многоугольник обходится против часовой стрелки, "верхние" рёбра (где движение идёт справа налево) дают отрицательный вклад, "нижние" — положительный, в сумме лишние площади под графиком сокращаются и остаётся ровно площадь многоугольника.

```c++
long double areaTrapezoid(const std::vector<Point>& poly) {
    long double S = 0;
    int n = poly.size();
    for (int i = 0; i < n; i++) {
        const Point& A = poly[i];
        const Point& B = poly[(i + 1) % n];
        S += (A.y + B.y) * (B.x - A.x);
    }
    return fabsl(S) / 2;
}
```

#### Объяснение

* каждое слагаемое — это удвоенная площадь трапеции под ребром $P_iP_{i+1}$, взятая со знаком (в зависимости от направления по $x$)
* суммируя по всем рёбрам, площади "под" верхней и "под" нижней частью контура вычитаются друг из друга, оставляя площадь самого многоугольника
* формула не зависит от того, где расположено начало координат — сдвиг всех точек не меняет результат, так как в сумме $\sum(y_i+y_{i+1})(x_{i+1}-x_i)$ константный сдвиг по $y$ сокращается (сумма $\sum(x_{i+1}-x_i)=0$ по замкнутому контуру)

---

## Способ 2: триангуляция из начала координат

### Идея

Разбиваем многоугольник на треугольники $OP_iP_{i+1}$, где $O$ — начало координат, и суммируем их площади со знаком.

Площадь треугольника $OP_iP_{i+1}$ через векторное произведение:

$$S_i = \frac{1}{2}(\vec{OP_i}\times\vec{OP_{i+1}})$$

```c++
long double areaTriangulation(const std::vector<Point>& poly) {
    long double S = 0;
    int n = poly.size();
    for (int i = 0; i < n; i++) {
        const Point& A = poly[i];
        const Point& B = poly[(i + 1) % n];
        S += (A ^ B);
    }
    return fabsl(S) / 2;
}
```

#### Объяснение

* знак $\vec{OP_i}\times\vec{OP_{i+1}}$ положителен, если поворот от $\vec{OP_i}$ к $\vec{OP_{i+1}}$ идёт против часовой стрелки, и отрицателен иначе
* если $O$ лежит внутри многоугольника — все треугольники накладываются без пересечений, и сумма их площадей сразу даёт площадь многоугольника
* если $O$ снаружи — часть треугольников "накрывает" область вне многоугольника с одним знаком, а часть "вычитает" её обратно с другим знаком (out-in-out эффект), и в итоге лишнее сокращается — поэтому формула работает **для любого $O$**, а не только для точки внутри
* по сути это то же самое, что метод трапеций: $\vec{OP_i}\times\vec{OP_{i+1}} = x_iy_{i+1}-x_{i+1}y_i$, что при суммировании и раскрытии скобок совпадает с формулой трапеций

---

## Общая формула (Гаусса / shoelace)

Обе реализации в коде считают буквально одно и то же выражение:

$$S = \frac{1}{2}\left|\sum_{i=1}^{n}(x_iy_{i+1}-x_{i+1}y_i)\right|$$

```c++
long double area(const std::vector<Point>& poly) {
    long double S = 0;
    int n = poly.size();
    for (int i = 0; i < n; i++) {
        const Point& A = poly[i];
        const Point& B = poly[(i + 1) % n];
        S += A.x * B.y - A.y * B.x;
    }
    return fabsl(S) / 2;
}
```

Без `fabsl` знак суммы даёт **ориентированную площадь**: положительна при обходе против часовой стрелки, отрицательна — по часовой. Это часто используют, чтобы определить ориентацию многоугольника без дополнительных проверок.

---

## Асимптотика

```c++
O(n)
```

Один проход по вершинам, на каждой — константное число операций.

---

## Применения

* вычисление площади произвольного (в том числе невыпуклого) многоугольника
* определение ориентации многоугольника (по часовой / против часовой) по знаку суммы
* проверка на самопересечение и построение выпуклой оболочки (площадь как вспомогательная величина)
* формула Пика (связь площади решётчатого многоугольника с числом точек на границе и внутри)

## Выпуклая оболочка (Convex Hull)

## Теория

Дан набор точек на плоскости. Нужно найти их **выпуклую оболочку** — минимальный выпуклый многоугольник, содержащий все точки.

Что нужно уметь делать:

* отсортировать точки в порядке, удобном для последовательного построения границы
* определять, образуют ли три последовательные точки поворот "не в ту сторону" (правый поворот при обходе против часовой стрелки), и в этом случае убирать среднюю точку

---

## Идея

**Алгоритм Грэхема** строит оболочку за счёт:

1. выбора опорной точки, гарантированно лежащей на оболочке
2. сортировки остальных точек по полярному углу относительно опорной
3. последовательного добавления точек со стеком, откуда выкидываются точки, образующие "невыпуклый" поворот

Ключевая идея: если при добавлении новой точки последний поворот в стеке оказывается по часовой стрелке (не левый) — верхушка стека не может быть частью выпуклой оболочки, её нужно убрать.

Поворот трёх точек $A,B,C$ определяется знаком векторного произведения:

$$\vec{AB}\times\vec{AC}$$

* $>0$ — поворот налево (против часовой стрелки)
* $<0$ — поворот направо (по часовой стрелке)
* $=0$ — точки коллинеарны

---

## Выбор опорной точки

Берём точку с минимальной $y$-координатой (при равенстве — с минимальной $x$). Такая точка гарантированно лежит на выпуклой оболочке, так как ниже и левее неё ничего нет.

```c++
int idx = 0;
for (int i = 1; i < (int) pts.size(); i++) {
    if (pts[i].y < pts[idx].y ||
        (pts[i].y == pts[idx].y && pts[i].x < pts[idx].x)) {
        idx = i;
    }
}
std::swap(pts[0], pts[idx]);
Point pivot = pts[0];
```

### Объяснение

* самая нижняя (и левая при равенстве) точка не может быть скрыта другими точками ни с какой стороны по вертикали — она заведомо угол оболочки
* эта точка становится центром, относительно которого дальше сортируются остальные

---

## Сортировка по полярному углу

Остальные точки сортируются по углу относительно `pivot`. Вместо вызова `atan2` (медленно и менее точно) сравнение делается через знак векторного произведения.

```c++
std::sort(pts.begin() + 1, pts.end(), [&](const Point& a, const Point& b) {
    long double cr = (a - pivot) ^ (b - pivot);
    if (sign(cr) != 0) {
        return cr > 0;
    }
    return (a - pivot).len2() < (b - pivot).len2();
});
```

### Объяснение

* $\vec{pivot,a}\times\vec{pivot,b}>0$ означает, что $b$ находится левее направления на $a$ — то есть угол до $a$ меньше угла до $b$, и `a` должна идти раньше
* при коллинеарности (`cr == 0`) точки лежат на одном луче из `pivot` — ближайшую ставим раньше, чтобы дальняя не потерялась (важно для случая нескольких точек на одной прямой у самого края оболочки)

---

## Построение оболочки

Проходим по отсортированным точкам, поддерживая стек. Пока последний поворот в стеке не левый — выкидываем предпоследнюю точку.

```c++
std::vector<Point> convexHull(std::vector<Point> pts) {
    int n = pts.size();
    if (n < 3) {
        return pts;
    }

    // выбор опорной точки и сортировка — см. выше

    std::vector<Point> hull;
    for (const Point& p : pts) {
        while (hull.size() >= 2) {
            Point& A = hull[hull.size() - 2];
            Point& B = hull[hull.size() - 1];
            if (sign((B - A) ^ (p - A)) > 0) {
                break;
            }
            hull.pop_back();
        }
        hull.push_back(p);
    }
    return hull;
}
```

### Объяснение "на пальцах"

* стек хранит текущую границу оболочки, построенную по уже обработанным точкам
* добавляя новую точку `p`, проверяем поворот на последних трёх точках стека ($A$, $B$, `p`)
* если поворот не левый (`<= 0`) — значит $B$ "провалилась" внутрь и не может быть углом оболочки, выкидываем её и проверяем снова с новой верхушкой
* каждая точка добавляется в стек и удаляется из него не более одного раза — отсюда линейная асимптотика самого прохода

---

## Асимптотика

* сортировка по углу — узкое место:

```c++
O(n log n)
```

* сам проход со стеком — каждая точка добавляется и удаляется не более одного раза:

```c++
O(n)
```

Итоговая асимптотика — $O(n\log n)$, определяется сортировкой.

---

## Применения

* нахождение минимального выпуклого многоугольника, содержащего набор точек
* задачи на диаметр множества точек (ротating calipers по оболочке)
* нахождение ближайшей/дальнейшей пары точек
* построение минимального охватывающего прямоугольника
* базовая структура для многих геометрических алгоритмов, где важна выпуклость

## Готовая реализация

```c++
std::vector<Point> convexHull(std::vector<Point> pts) {
    int n = pts.size();
    if (n < 3) {
        return pts;
    }

    int idx = 0;
    for (int i = 1; i < n; i++) {
        if (pts[i].y < pts[idx].y ||
            (pts[i].y == pts[idx].y && pts[i].x < pts[idx].x)) {
            idx = i;
        }
    }
    std::swap(pts[0], pts[idx]);
    Point pivot = pts[0];

    std::sort(pts.begin() + 1, pts.end(), [&](const Point& a, const Point& b) {
        long double cr = (a - pivot) ^ (b - pivot);
        if (sign(cr) != 0) {
            return cr > 0;
        }
        return (a - pivot).len2() < (b - pivot).len2();
    });

    std::vector<Point> hull;
    for (const Point& p : pts) {
        while (hull.size() >= 2) {
            Point& A = hull[hull.size() - 2];
            Point& B = hull[hull.size() - 1];
            if (sign((B - A) ^ (p - A)) > 0) {
                break;
            }
            hull.pop_back();
        }
        hull.push_back(p);
    }
    return hull;
}
```

## Точка в выпуклом многоугольнике за $O(\log n)$

### Теория

Дан выпуклый многоугольник $P_0,P_1,\dots,P_{n-1}$ (вершины упорядочены против часовой стрелки) и точка $Q$. Нужно определить, лежит ли $Q$ внутри многоугольника, за $O(\log n)$ на запрос (после $O(n)$ предподсчёта).

---

### Идея

Из вершины $P_0$ многоугольник разбивается диагоналями на $n-2$ треугольника $P_0P_iP_{i+1}$, которые вместе покрывают весь многоугольник и упорядочены по углу вокруг $P_0$ — это и позволяет искать нужный треугольник **бинпоиском**.

Точка $Q$ лежит в многоугольнике тогда и только тогда, когда:

1. $Q$ лежит внутри угла $P_1P_0P_{n-1}$ (то есть между первым и последним "веерными" векторами)
2. в найденном по бинпоиску секторе $P_0P_iP_{i+1}$ точка лежит с той же стороны от $P_iP_{i+1}$, что и внутренность многоугольника

---

### Проверка попадания в угол веера

```c++
bool insideFan(const std::vector<Point>& P, const Point& Q) {
    Point v1 = P[1] - P[0];
    Point vn = P[P.size() - 1] - P[0];
    Point vq = Q - P[0];

    if (sign(v1 ^ vq) < 0 || sign(vq ^ vn) < 0) {
        return false;
    }
    return true;
}
```

#### Объяснение

* веер векторов из $P_0$ отсортирован по углу от $\vec{P_0P_1}$ до $\vec{P_0P_{n-1}}$ (обход против часовой стрелки)
* если $Q$ находится правее первого вектора или левее последнего — она гарантированно вне многоугольника, дальше искать нечего

---

### Бинарный поиск сектора

```c++
int findSector(const std::vector<Point>& P, const Point& Q) {
    int lo = 1, hi = (int) P.size() - 1;
    while (hi - lo > 1) {
        int mid = (lo + hi) / 2;
        if (sign((P[mid] - P[0]) ^ (Q - P[0])) >= 0) {
            lo = mid;
        } else {
            hi = mid;
        }
    }
    return lo;
}
```

#### Объяснение

* ищем такой индекс `lo`, что $Q$ лежит между лучами $\vec{P_0P_{lo}}$ и $\vec{P_0P_{hi}}$
* условие `(P[mid]-P[0]) ^ (Q-P[0]) >= 0` означает "$Q$ левее или на луче до $P_{mid}$" — если это так, сектор нужно искать правее (`mid` можно сдвигать вправо), иначе — левее
* за счёт упорядоченности векторов по углу, эта проверка монотонна, что и позволяет бинарный поиск

### Финальная проверка

```c++
bool pointInConvexPolygon(const std::vector<Point>& P, const Point& Q) {
    if (!insideFan(P, Q)) {
        return false;
    }
    int i = findSector(P, Q);
    return sign((P[i + 1] - P[i]) ^ (Q - P[i])) >= 0;
}
```

#### Объяснение

* после того как сектор $P_0P_iP_{i+1}$ найден, осталось проверить последнее ребро — сторону $P_iP_{i+1}$
* если $Q$ лежит слева от него (или на нём) — точка внутри многоугольника, иначе снаружи

---

### Асимптотика

```c++
O(log n)
```

Один бинарный поиск по индексу вершины, всё остальное — константа.

## Точка в невыпуклом многоугольнике

Для невыпуклого многоугольника бинпоиском по углу от одной вершины не обойтись — веер из $P_0$ уже не покрывает многоугольник без наложений. Используются два линейных по времени метода.

---

### Метод горизонтального луча (ray casting)

#### Идея

Пускаем из $Q$ луч в произвольном фиксированном направлении (обычно горизонтально вправо) и считаем число пересечений с рёбрами многоугольника.

* чётное число пересечений — точка снаружи
* нечётное число пересечений — точка внутри

Интуиция: каждое пересечение переключает "внутри/снаружи", как переключатель; луч из точки, гарантированно лежащей вне многоугольника, стартует "снаружи".

```c++
bool pointInPolygonRay(const std::vector<Point>& P, const Point& Q) {
    int n = P.size();
    bool inside = false;

    for (int i = 0; i < n; i++) {
        Point A = P[i], B = P[(i + 1) % n];

        if (sign(A.y - Q.y) == 0 && sign(B.y - Q.y) == 0) {
            continue;
        }
        if ((A.y > Q.y) != (B.y > Q.y)) {
            long double xCross = A.x + (Q.y - A.y) * (B.x - A.x) / (B.y - A.y);
            if (xCross > Q.x) {
                inside = !inside;
            }
        }
    }
    return inside;
}
```

#### Объяснение "на пальцах"

* ребро пересекает горизонтальный луч из $Q$, только если один его конец строго выше $Q.y$, а другой строго ниже (`(A.y > Q.y) != (B.y > Q.y)`) — это отсекает рёбра, которые не пересекают уровень $Q.y$ вовсе
* для такого ребра находим $x$-координату пересечения с прямой $y=Q.y$ и сравниваем с $Q.x$: если пересечение правее $Q$ — луч вправо задевает это ребро
* горизонтальные рёбра (`A.y == B.y == Q.y`) пропускаются отдельно — они не пересекают луч в обычном смысле, лишь совпадают с ним, что требует особой обработки (иначе двойной счёт на вершинах)
* сравнение через `>` (строго), а не `>=`, в паре с условием `!=` на `y` — стандартный трюк, чтобы точка, через которую луч проходит ровно по вершине многоугольника, не считалась дважды

---

### Метод суммы углов (winding number)

#### Идея

Суммируем ориентированные углы $\angle P_iQP_{i+1}$ при обходе всех вершин многоугольника, если смотреть на них из точки $Q$.

* если $Q$ внутри — суммарный угол равен $\pm 2\pi$ (полный оборот)
* если $Q$ снаружи — суммарный угол равен $0$ (обороты компенсируются)

```c++
bool pointInPolygonAngles(const std::vector<Point>& P, const Point& Q) {
    int n = P.size();
    long double sumAngle = 0;

    for (int i = 0; i < n; i++) {
        Point A = P[i] - Q;
        Point B = P[(i + 1) % n] - Q;

        if (sign(A.len()) == 0 || sign(B.len()) == 0) {
            return true;
        }

        long double angle = atan2l(A ^ B, A * B);
        sumAngle += angle;
    }

    return sign(fabsl(sumAngle) - PI) > 0;
}
```

#### Объяснение "на пальцах"

* `atan2l(A ^ B, A * B)` даёт ориентированный угол поворота от $\vec{QP_i}$ к $\vec{QP_{i+1}}$, со знаком, в диапазоне $(-\pi,\pi]$
* если $Q$ внутри контура — при полном обходе вершин эти углы "накручивают" ровно один полный оборот ($\approx\pm2\pi$)
* если $Q$ снаружи — углы туда-обратно компенсируются, суммарно получается $\approx0$
* сравнение с $\pi$ (а не с $0$ или $2\pi$) — просто удобный порог посередине, чтобы не зависеть от точности плавающей точки при сравнении с самими $0$ и $2\pi$
* попадание $Q$ ровно на вершину обрабатывается отдельным early return

---

### Асимптотика

Оба метода:

```c++
O(n)
```

Один линейный проход по рёбрам многоугольника. Метод углов на практике медленнее из-за вызовов `atan2` на каждой итерации, метод луча — стандартный выбор на практике.

---

## Применения

* проверка принадлежности точки многоугольнику (в том числе с самопересечениями и "дырками" — через тот же winding number с учётом кратности)
* точка в выпуклой оболочке за $O(\log n)$ — как ускоренная проверка при большом числе запросов к одному и тому же многоугольнику
* задачи компьютерной графики (растеризация многоугольников, hit-testing)
* точка в объединении/пересечении многоугольников через комбинацию проверок

## Касательная к выпуклому многоугольнику из точки

### Теория

Дан выпуклый многоугольник $P_0,P_1,\dots,P_{n-1}$ (вершины против часовой стрелки) и точка $Q$ снаружи него. Нужно найти две **опорные вершины** (точки касания) — такие $P_i$ и $P_j$, что прямые $QP_i$ и $QP_j$ не пересекают внутренность многоугольника, а весь многоугольник лежит между ними (по одну сторону от каждой касательной).

Аналог задачи "касательная из точки к окружности", но для многоугольника: касательных тоже ровно две, они ограничивают "видимую" из $Q$ часть контура.

---

### Идея

Вершина $P_i$ — точка касания, если обе соседние с ней вершины $P_{i-1}$ и $P_{i+1}$ лежат **по одну сторону** от прямой $QP_i$ (или на ней). Это прямой аналог условия "локального экстремума": в точке касания направление $\vec{QP_i}\to\vec{QP_{i+1}}$ меняет знак поворота.

За счёт выпуклости многоугольника, если пройтись по вершинам и смотреть на знак поворота $\vec{QP_i}\times\vec{QP_{i+1}}$, он меняется **не более двух раз** за полный обход — это и даёт возможность искать точки касания бинарным поиском, а не перебором за $O(n)$.

Функция "поворот в вершине $i$" (знак $\vec{P_{i-1}P_i}\times\vec{P_iP_{i+1}}$ относительно $Q$) — по сути унимодальна на кольце вершин, что типично для выпуклых оболочек: одна точка касания разделяет "верхнюю" дугу (где повороты идут в одну сторону) от "нижней".

---

### Определение стороны в вершине

```c++
int side(const std::vector<Point>& P, int i, const Point& Q) {
    int n = P.size();
    Point prev = P[(i - 1 + n) % n];
    Point next = P[(i + 1) % n];

    long double cr1 = (P[i] - Q) ^ (prev - Q);
    long double cr2 = (P[i] - Q) ^ (next - Q);

    return sign(cr1) >= 0 && sign(cr2) >= 0 ? 1 : -1;
}
```

#### Объяснение

* `cr1`, `cr2` — знаки поворота от направления $QP_i$ к соседним вершинам
* если обе соседние вершины лежат **левее или на** луче $QP_i$ (обе $\geqslant 0$) — вершина $P_i$ является точкой касания (одна из двух), возвращаем `1`
* иначе вершина "внутри" видимой дуги или "снаружи" — возвращаем `-1`, это и есть сигнал для бинпоиска, в какую сторону двигаться

---

### Бинарный поиск точки касания

Ищем индекс вершины, где `side` меняется — то есть саму точку касания. Делаем это дважды: для верхней и для нижней касательной, стартуя поиск с противоположных концов массива вершин.

```c++
int findTangent(const std::vector<Point>& P, const Point& Q, int dir) {
    int n = P.size();
    int lo = 0, hi = n;

    while (hi - lo > 1) {
        int mid = (lo + hi) / 2;
        long double cr = (P[mid % n] - Q) ^ (P[(mid + dir + n) % n] - Q);

        if (sign(cr) * dir >= 0) {
            lo = mid;
        } else {
            hi = mid;
        }
    }
    return lo % n;
}
```

#### Объяснение "на пальцах"

* `dir = 1` ищет одну касательную (обход "вперёд"), `dir = -1` — другую (обход "назад")
* знак `cr` показывает, продолжает ли контур "уходить" от $Q$ в текущем направлении обхода, или уже начал "заворачивать назад" — момент разворота и есть точка касания
* за счёт выпуклости этот знак монотонен на каждой из двух половин многоугольника (разделённых точками касания), что и делает возможным бинарный поиск вместо полного перебора

---

### Нахождение обеих касательных

```c++
std::pair<int, int> tangentsFromPoint(const std::vector<Point>& P, const Point& Q) {
    int t1 = findTangent(P, Q, 1);
    int t2 = findTangent(P, Q, -1);
    return {t1, t2};
}
```

Возвращает индексы двух вершин касания. Сами касательные прямые — это прямые $QP_{t_1}$ и $QP_{t_2}$.

---

### Асимптотика

```c++
O(log n)
```

Два независимых бинарных поиска по массиву вершин, каждый — за $O(\log n)$.

---

### Применения

* построение общей видимой области многоугольника из внешней точки
* объединение выпуклых многоугольников (слияние оболочек, где нужны общие касательные)
* задачи на видимость / обход препятствия-многоугольника кратчайшим путём
* поддержка динамической выпуклой оболочки, где после добавления точки старая оболочка "подрезается" по касательным из новой точки

## Касательные к выпуклому многоугольнику, параллельные данной прямой

### Теория

Дан выпуклый многоугольник $P_0,P_1,\dots,P_{n-1}$ (вершины против часовой стрелки) и направление — прямая с направляющим вектором $\vec d$. Нужно найти две **опорные прямые**, параллельные $\vec d$ и касающиеся многоугольника с двух противоположных сторон (то есть весь многоугольник лежит между ними).

Точки касания — это вершины, где многоугольник **дальше всего** заходит в направлении $\vec d$ и в направлении $-\vec d$ соответственно (экстремумы проекции на $\vec d$).

---

### Идея

Проекция вершины $P_i$ на направление $\vec d$ — это скалярное произведение $\vec d\cdot P_i$. Нужно найти вершину, максимизирующую эту проекцию (одна касательная), и вершину, минимизирующую её (вторая, противоположная).

Ключевой факт выпуклости: последовательность проекций $\vec d\cdot P_0,\ \vec d\cdot P_1,\dots$ при обходе по кругу сначала возрастает, потом убывает (**унимодальна**, как гора с одним пиком и одной впадиной на цикле) — это то же свойство, что используется в задаче с касательной из точки, только теперь функция сравнения не поворот относительно $Q$, а сама проекция на $\vec d$.

Значит вершину-максимум и вершину-минимум можно искать бинарным поиском, а не перебором за $O(n)$.

---

### Проверка направления возрастания в вершине

```c++
long double proj(const Point& d, const Point& P) {
    return d * P;
}

int risingAt(const std::vector<Point>& P, const Point& d, int i) {
    int n = P.size();
    long double cur = proj(d, P[i]);
    long double next = proj(d, P[(i + 1) % n]);
    return sign(next - cur) >= 0 ? 1 : -1;
}
```

#### Объяснение

* сравниваем проекцию текущей вершины со следующей: если проекция растёт — мы ещё на "подъёме" к пику, если падает — уже "спускаемся"
* по унимодальности этот признак используется как условие для бинарного поиска пика и впадины

---

### Бинарный поиск вершины с максимальной проекцией

```c++
int findMaxProjection(const std::vector<Point>& P, const Point& d) {
    int n = P.size();
    int lo = 0, hi = n;

    while (hi - lo > 1) {
        int mid = (lo + hi) / 2;
        if (risingAt(P, d, mid % n) > 0) {
            lo = mid;
        } else {
            hi = mid;
        }
    }
    return (lo + 1) % n;
}
```

#### Объяснение "на пальцах"

* пока проекция растёт (`risingAt > 0`) — двигаем `lo` вправо, мы ещё не дошли до пика
* как только начинается спад — сужаем интервал слева
* в итоге `lo+1` указывает на вершину с максимальной проекцией на $\vec d$ — это и есть точка касания одной из двух опорных прямых

### Вершина с минимальной проекцией

Для второй (противоположной) касательной ищем максимум проекции на $-\vec d$ — это то же самое, что минимум проекции на $\vec d$:

```c++
int findMinProjection(const std::vector<Point>& P, const Point& d) {
    return findMaxProjection(P, {-d.x, -d.y});
}
```

---

### Нахождение обеих касательных

```c++
std::pair<int, int> tangentsParallelToLine(const std::vector<Point>& P, const Point& d) {
    int t1 = findMaxProjection(P, d);
    int t2 = findMinProjection(P, d);
    return {t1, t2};
}
```

Обе искомые касательные — это прямые, проходящие через $P_{t_1}$ и через $P_{t_2}$, с направляющим вектором $\vec d$.

---

### Асимптотика

```c++
O(log n)
```

Два независимых бинарных поиска по массиву вершин, каждый — за $O(\log n)$.

* метод вращающихся калиперов (rotating calipers) — перебор всех направлений через рёбра многоугольника для поиска диаметра, минимального охватывающего прямоугольника и т.п.
