# Bipartite Matching (Kuhn's Algorithm, наибольшее паросочетание)

## Теория

### Определения

- **Паросочетание** — множество рёбер, не пересекающихся по вершинам
- **Максимальное паросочетание** — паросочетание, в которое нельзя добавить ни одного ребра
- **Наибольшее паросочетание** — максимальное паросочетание с наибольшим количеством рёбер
- **Свободная вершина** — вершина, не покрытая ни одним ребром паросочетания
- **Удлиняющий путь** (augmenting path) — путь между двумя свободными вершинами, в котором рёбра чередуются: не из
паросочетания / из паросочетания / .... Рёбер вне паросочетания в нём на одно больше, чем рёбер паросочетания

Нужно уметь:

- находить наибольшее паросочетание в двудольном графе
- проверять его оптимальность
- эффективно наращивать паросочетание удлиняющими путями

---

## Идея

- в основе — **лемма Бёржа**: паросочетание наибольшее тогда и только тогда, когда для него нет удлиняющего пути
- значит алгоритм — искать удлиняющие пути, пока они находятся, и каждый раз увеличивать паросочетание на 1 ребро
- инвариант: у каждой вершины правой доли не более одного ребра паросочетания — храним `p[v]` — вершину левой доли,
cопоставленную с `v`
- рёбра ориентируем слева направо, рёбра паросочетания — справа налево

### Почему удлиняющий путь увеличивает паросочетание

- если инвертировать рёбра вдоль удлиняющего пути (убрать рёбра паросочетания, добавить остальные), получится
паросочетание на 1 ребро больше
- значит, пока такой путь существует, текущее паросочетание — не наибольшее

### Доказательство леммы Бёржа "на пальцах"

- пусть `G` — текущее паросочетание, `G'` — наибольшее, причём `|G'| > |G|`
- рассмотрим симметрическую разность:

```c++
D = G △ G'
```

- у каждой вершины в `D` степень не больше `2` (не больше одного ребра из `G` и одного из `G'`) → `D` распадается на
простые пути и циклы
- в циклах рёбра `G` и `G'` строго чередуются → рёбер каждого типа поровну
- так как `|G'| > |G|`, найдётся путь, у которого оба крайних ребра из `G'`
- концы этого пути свободны относительно `G` (иначе к пути можно добавить ещё ребро `G'`) → это удлиняющий путь для `G`
- получили противоречие с тем, что удлиняющих путей нет

**Вывод:** можно жадно искать удлиняющие пути, пока они есть — в конце паросочетание гарантированно наибольшее.

---

## Поиск удлиняющего пути (dfs Куна)

Функция `kuhn(u)` пытается найти удлиняющий путь, начинающийся в свободной вершине `u` левой доли.

```c++
bool kuhn(int u) {
    if (used[u] == timer) {
        return false;
    }
    used[u] = timer;
    for (int v : g[u]) {
        if (p[v] == -1) {
            p[v] = u;
            return true;
        }
    }
    for (int v : g[u]) {
        if (kuhn(p[v])) {
            p[v] = u;
            return true;
        }
    }
    return false;
}
```

### Идея dfs

- сначала пробуем найти **свободную** вершину справа — путь длины 1, самый дешёвый случай
- если все соседи заняты, пытаемся "перевыдать" одну из занятых вершин: рекурсивно ищем удлиняющий путь для того, с кем
она сейчас сопоставлена (`p[v]`)
- если рекурсия нашла путь — освобождённое место занимает `u`
- `used` защищает от повторного захода в одну вершину левой доли за один dfs

---

## Основной цикл алгоритма

Перебираем все вершины левой доли и пытаемся найти для каждой удлиняющий путь.

```c++
std::fill(p.begin(), p.end(), -1);
for (int u = 0; u < n; u++) {
    timer++;
    kuhn(u);
}
```

### Зачем `timer` вместо очистки `used`

- каждый вызов внешнего цикла требует "чистого" массива `used`
- вместо `std::fill(used, false)` за `O(n)` перед каждым запуском — увеличиваем счётчик `timer` за `O(1)`
- вершина считается посещённой в текущем dfs, если `used[u] == timer`

---

## Асимптотика

- один `kuhn` — обход по рёбрам графа: `O(n + m)`
- внешний цикл запускает его `n` раз

```c++
O(n * (n + m))
```

---

## Применения

- задачи о наибольшем паросочетании в двудольных графах
- задачи о назначениях (распределение работ, покрытие)
- частный случай задачи о максимальном потоке
- построение независимого множества / вершинного покрытия через теорему Кёнига
- задачи на потоки с ограничением по вершинам

## Готовая реализация

```c++
int n, m;
std::vector<std::vector<int>> g;
std::vector<int> p, used;
int timer = 0;

bool kuhn(int u) {
    if (used[u] == timer) {
        return false;
    }
    used[u] = timer;
    for (int v : g[u]) {
        if (p[v] == -1) {
            p[v] = u;
            return true;
        }
    }
    for (int v : g[u]) {
        if (kuhn(p[v])) {
            p[v] = u;
            return true;
        }
    }
    return false;
}

p.assign(m, -1);
used.assign(n, 0);

for (int u = 0; u < n; u++) {
    timer++;
    kuhn(u);
}
```

## Лемма Холла (Hall's theorem)

**Условие Холла** для двудольного графа с долями `X` и `Y`: паросочетание, покрывающее всю долю `X`, существует тогда и
только тогда, когда для любого подмножества `A ⊆ X` выполняется:

```c++
|N(A)| >= |A|
```

где `N(A)` — множество вершин `Y`, соединённых хотя бы с одной вершиной из `A`.

### Идея "на пальцах"

- необходимость очевидна: если у какого-то `A` соседей меньше, чем вершин в нём самом, покрыть все вершины `A` разными
вершинами `Y` физически нельзя
- достаточность доказывается от противного через лемму Бёржа:
    - если наибольшее паросочетание не покрывает `X` целиком, найдётся свободная вершина `u ∈ X`
    - рассмотрим все вершины, достижимые из `u` чередующимся путём (не из паросочетания / из паросочетания / ...) —
назовём это множество `A` (в `X`) и `N(A)` (в `Y`)
    - если бы у `A` был сосед вне текущего `N(A)`, до него можно было бы дойти чередующимся путём — и это давало бы
удлиняющий путь, что противоречит наибольшести паросочетания
    - значит все соседи `A` уже покрыты, и каждый из них сопоставлен вершине внутри `A`
    - тогда `|N(A)| = |A| - 1 < |A|` (вершина `u` не сопоставлена) — нарушено условие Холла

**Вывод:** условие Холла — это ровно тот критерий, который гарантирует существование полного по `X` паросочетания.
Алгоритм Куна на практике и есть конструктивное доказательство: если он не смог сопоставить вершину `u`, то найденное
множество `A` — свидетель нарушения условия Холла.

## Минимальное вершинное покрытие и теорема Кёнига

**Вершинное покрытие** — множество вершин, такое что каждое ребро графа инцидентно хотя бы одной вершине из этого
множества.

**Теорема Кёнига.** В двудольном графе размер наибольшего паросочетания равен размеру минимального вершинного покрытия:

```c++
|M_max| == |C_min|
```

### Идея построения покрытия по паросочетанию

- строим наибольшее паросочетание `M` алгоритмом Куна
- запускаем обход (dfs/bfs) по чередующимся путям из всех **свободных** вершин левой доли `X`, двигаясь по рёбрам не из
`M` в `Y` и по рёбрам из `M` обратно в `X`
- пусть `Z` — множество всех вершин, достижимых такими чередующимися путями
- тогда минимальное вершинное покрытие:

```c++
C = (X \ Z) ∪ (Y ∩ Z)
```

### Почему это работает "на пальцах"

- **это покрытие**: любое ребро либо не входит в `M` — тогда его левый конец не может лежать в `Z`-непосещённой части
`X` (иначе правый конец тоже был бы достижим и попал в покрытие через `Y ∩ Z`), либо входит в `M` — тогда ровно один его
конец обязан лежать в `C` по построению обхода
- **размер совпадает с `|M|`**: каждой вершине `C` соответствует ровно одно своё ребро паросочетания (свободные вершины
`X` не входят в `C`, так как они все в `Z`; вершины `Y ∩ Z` всегда покрыты рёбрами `M`, иначе через них шёл бы
удлиняющий путь) — значит `|C| = |M|`
- а по лемме Кёнига (легко) `|C| >= |M|` для любого покрытия и любого паросочетания — значит это покрытие минимально

## Наибольшее независимое множество (МНМ)

**Независимое множество** — множество вершин графа, никакие две из которых не соединены ребром.

**Наибольшее независимое множество** — независимое множество максимального размера.

### Связь с вершинным покрытием

**Statement.** Множество вершин `S` независимо тогда и только тогда, когда его дополнение `V \ S` — вершинное покрытие.

- если `S` независимо — то каждое ребро графа не может иметь оба конца в `S` → хотя бы один конец лежит в `V \ S` → это
покрытие
- и наоборот: если `V \ S` — покрытие, то никакое ребро не может целиком лежать в `S` (иначе оно не было бы покрыто) →
`S` независимо

Отсюда:

```c++
|S_max| = |V| - |C_min|
```

то есть наибольшее независимое множество — это дополнение минимального вершинного покрытия.

### Построение для двудольного графа

Раз для двудольных графов есть теорема Кёнига (`|C_min| = |M_max|`), наибольшее независимое множество можно построить
конструктивно:

- находим наибольшее паросочетание `M` алгоритмом Куна
- строим `Z` — множество вершин, достижимых чередующимися путями из свободных вершин левой доли `X` (как при построении
минимального покрытия)
- минимальное покрытие: `C = (X \ Z) ∪ (Y ∩ Z)`
- тогда наибольшее независимое множество — это его дополнение:

```c++
S = (X ∩ Z) ∪ (Y \ Z)
```

### Идея "на пальцах"

- покрытие и независимое множество — это буквально одно и то же разбиение вершин, только с разных сторон
- минимизируя покрытие, автоматически максимизируем его дополнение
- поэтому для двудольных графов задача сводится к уже решённой задаче о паросочетании — отдельный алгоритм не нужен
